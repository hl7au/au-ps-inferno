# Security, Safety and Privacy

This statement covers the AU PS Inferno Test Kit (`au_ps_inferno`) and its use on the
HL7 AU Inferno service at <https://inferno.hl7.org.au/test-kits/au-ps/>.

It is provided to meet the "Security safety and privacy issues statement" requirement of the
HL7 AU technical project publication process
([Process: HL7 AU Technical Projects](https://confluence.hl7.org/display/HA/Process%3A+HL7+AU+Technical+Projects), step 5).

## What this software is

The AU PS Inferno Test Kit is developer tooling. It checks whether a FHIR server or an
AU Patient Summary Bundle conforms to the
[AU Patient Summary Implementation Guide](https://hl7.org.au/fhir/ps/). It is built on
[Inferno Core](https://github.com/inferno-framework/inferno-core) and uses the
[HL7 FHIR Validator](https://github.com/hapifhir/org.hl7.fhir.validator-wrapper).

It is not a clinical system, it does not provide clinical functionality, and it is not part of
any patient care pathway.

## Safety

- **Test results are indicative, not a certification.** A passing result means the tests that
  were run did not detect a conformance problem. It is not a statement that an implementation is
  conformant, fit for purpose, or clinically safe.
- **Coverage is partial by design.** The test kit checks the requirements described in the test
  descriptions. Absence of a test is not evidence of conformance. Open and deferred checks are
  tracked in the [issue tracker](https://github.com/hl7au/au-ps-inferno/issues).
- **Results depend on the validator version.** The validator and IG package versions used for a
  run are surfaced in the validation output so a result can be interpreted and reproduced.
- **Do not use this tool to make clinical decisions**, and do not present its output as evidence
  of clinical safety or regulatory compliance.

## Privacy

- **Use synthetic or de-identified data only. Do not submit real patient data.** The test kit is
  intended to be exercised with test data such as the AU PS example Bundles or synthetic data.
- **What the test kit processes.** Depending on the group you run, it processes an AU PS Bundle
  that you paste in, one it retrieves from a URL or FHIR server you nominate, or one generated by
  calling `$summary` on a server you nominate. It also reads a server's CapabilityStatement.
- **Session data is retained.** On the hosted service, inputs, requests, responses and results are
  stored against a test session so that results can be revisited. Anything you submit, including
  the contents of a Bundle, is retained as part of that session.
- **Session links are not access controlled.** A test session is addressed by an unguessable
  identifier in its URL. Anyone who obtains that URL can view the session and its data. Treat
  session URLs as sensitive and do not publish them if the session contains anything you would
  not publish.
- **Request headers are visible in the session.** Any headers you configure, including
  authorisation headers, are used for outbound requests and are visible in the session's Requests
  tab.
- **Run it locally for anything sensitive.** The test kit can be run entirely on your own
  infrastructure with Docker (see the README). If your data cannot be shared with a public
  service, use a local deployment.

## Security

- **The public service is unauthenticated.** <https://inferno.hl7.org.au> is a public testing
  service. There is no user account or login, and sessions are separated only by their identifier.
- **Do not enter long lived or production credentials.** If a test needs to authenticate to your
  server, prefer a short lived token scoped to a test environment, and revoke it afterwards.
  Credentials entered as inputs are stored with the session.
- **Outbound requests.** The test kit issues requests only to the endpoints you supply, plus the
  configured FHIR validator. It does not proxy traffic between unrelated sessions.
- **Dependencies.** Security fixes reach the test kit through updates to Inferno Core, the FHIR
  Validator wrapper and Ruby gem dependencies. Dependency versions are pinned in `Gemfile.lock`
  and updated as part of normal maintenance.
- **Supply chain.** Releases are published from tagged commits in this repository by an automated
  workflow that verifies the release tag matches the gem version. The gem is published to
  [RubyGems](https://rubygems.org/gems/au_ps_inferno) and the source is Apache 2.0 licensed.

## Reporting a security or privacy concern

**Please do not open a public GitHub issue for a suspected vulnerability.**

Report it privately to the project maintainers:

- Email the project lead at <kyle.pettigrew@csiro.au>, or
- Email HL7 Australia projects at <projects@hl7.au>

Please include enough detail to reproduce the problem, and where relevant the affected version.
We will acknowledge the report, assess it, and coordinate any fix and disclosure with you. If a
fix requires a release, it will be recorded in [CHANGELOG.md](CHANGELOG.md).

For non-security bugs, feature requests and general feedback, use the
[issue tracker](https://github.com/hl7au/au-ps-inferno/issues) or the
[Inferno Test Kit feedback topic](https://chat.fhir.org/#narrow/channel/179173-australia/topic/Inferno.20Test.20Kit.20feedback.20and.20queries)
on chat.fhir.org, as described in the README.

## Supported versions

Fixes are made against the latest released version of the test kit. Earlier versions are not
patched. Released versions are listed in
[Releases](https://github.com/hl7au/au-ps-inferno/releases) and in
[CHANGELOG.md](CHANGELOG.md).
